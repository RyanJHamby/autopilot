# Model selection, token efficiency, and cost tracking for coding-agent workflows

Fetched 2026-10-29 (all vendor pages fetched that day). Labels: [MEASURED] = a number from a benchmark/eval with stated setup; [VENDOR-CLAIMED] = vendor statement without reproducible method; [DOC] = official price/spec; [DERIVED] = my arithmetic from [DOC] numbers; [ANECDOTAL] = single report. Tooling note: this run had WebFetch only (no web search), so practitioner coverage (Willison, Hamel Husain, Eugene Yan, Latent Space) is thin; see Gaps.

## Model tiering and routing: what to use for which task class, and what savings are published

### Takeaway
Anthropic's own docs recommend Haiku for simple/fast and subagent work, Sonnet for daily coding, Opus for complex reasoning, and Fable for the hardest/longest tasks; they also ship two built-in mixed-model patterns (`opusplan`, and an "advisor" tool where a cheaper main model consults a stronger one). Published routing research (RouteLLM, FrugalGPT) shows large savings (35-85%+, up to 98% claimed) but on chat/QA benchmarks with GPT-4-era models, not on coding agents, and Anthropic's advisor post is the only first-party agentic number I found (small gain, ~12% cheaper on SWE-bench Multilingual).

### Cited Findings
- Claude Code alias guidance [DOC]: `haiku` = simple, fast tasks; `sonnet` = daily coding; `opus` = complex reasoning; `fable` = hardest and longest-running tasks (root-cause investigations, outage debugging, architecture decisions); `opusplan` = Opus in plan mode, Sonnet for execution. Fable is never the default on any plan; Opus 5.5 is the default on Pro/Max/Team/Enterprise/API. — [Model config](https://code.claude.com/docs/en/model-config)
- Cost doc [DOC]: "Sonnet handles most coding tasks well and costs less than Opus. Reserve Opus for complex architectural decisions or multi-step reasoning." For simple subagent tasks set `model: haiku`. Subagents inherit the session model by default, so switching to Opus before delegating makes subagents Opus too. — [Costs](https://code.claude.com/docs/en/costs)
- Subagent model resolution order [DOC]: per-invocation model param, then subagent frontmatter `model`, then `CLAUDE_CODE_SUBAGENT_MODEL`, then main model. Built-in Explore uses the main model (Opus alias if main is Fable on subscription/Console); to make Explore cheaper, define a user/project subagent named `Explore` with `model: haiku`. claude-code-guide runs on Haiku, statusline-setup on Sonnet. — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Effort is a second cost dial [DOC]: levels low/medium/high/xhigh/max; Opus 5.5, Sonnet 5.5, Haiku 5.5 default to medium; "medium ... reduces token use"; "max ... may overthink". Thinking tokens are billed as output even when collapsed. You cannot turn thinking off on Opus 5.5, Sonnet 5.5, Haiku 5.5, or Fable. — [Model config](https://code.claude.com/docs/en/model-config); [Costs](https://code.claude.com/docs/en/costs)
- Agent teams: ~7x tokens vs standard sessions when teammates run in plan mode; docs say use Sonnet for teammates, keep teams small. [VENDOR-CLAIMED, approximate] — [Costs](https://code.claude.com/docs/en/costs)
- Advisor tool (experimental, Anthropic API only) [DOC]: a main model consults a stronger advisor at decision points (before committing to an approach, on recurring errors, before declaring done). Advisor must rank at or above the main model. Pairings listed: Sonnet+Opus, Sonnet+Fable, Haiku+Opus ("lowest-cost main model with strong planning ... higher cost than Haiku alone but lower than switching the main model to Sonnet or Opus"), Opus+Opus for independent check. The advisor re-reads the full transcript each call with no caching; toggling the advisor does not invalidate the main cache. No setting caps advisor calls. — [Advisor](https://code.claude.com/docs/en/advisor)
- Advisor strategy results [VENDOR-CLAIMED benchmarks, Anthropic-run, older model gen]: Sonnet 4.6 + Opus 4.6 advisor vs Sonnet 4.6 solo on SWE-bench Multilingual: +2.7 points and 11.9% lower cost per agentic task. Haiku 4.5 + Opus 4.6 advisor on BrowseComp: 41.2% vs 19.7% for Haiku solo, and "85% less per task" than Sonnet solo (baseline not explicitly named in the post per the fetch summary). Advisor emits ~400-700 text tokens per plan at Opus rates. Customer-reported (Eve Legal): Haiku 4.5 + Opus advisor matched frontier quality on structured extraction at 5x lower cost [ANECDOTAL/customer]. Other benchmark figures are in charts only. — [The advisor strategy](https://claude.com/blog/the-advisor-strategy)
- Multi-agent research system (Anthropic) [VENDOR-CLAIMED, internal eval]: Opus 4 lead + Sonnet 4 subagents beat single-agent Opus 4 by 90.2% on their research eval; agents use ~4x chat tokens, multi-agent ~15x; on BrowseComp token usage alone explained ~80% of performance variance; upgrading to Sonnet 4 beat doubling token budget on Sonnet 3.7. Post says "most coding tasks" have fewer parallelizable parts than research, so multi-agent is a poor fit there. — [Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- RouteLLM (LMSYS) [MEASURED, GPT-4 Turbo vs Mixtral 8x7B, chat/QA benchmarks]: MT-Bench cost reduction >85% at 95% of GPT-4 performance (with data augmentation; matrix-factorization router needed 14% GPT-4 calls vs 26% with Arena data only); MMLU ~45% and GSM8K ~35% cost reduction headline; on MMLU with Arena data only routers were near random (out-of-distribution), and with ~1,500 golden-label augmentation the best router still needed 54% GPT-4 calls for 95% performance (~14% cheaper than random). Routers transferred without retraining to Claude 3 Opus / Llama 3 8B. Matched commercial routers (Martian, Unify) at >40% lower cost. — [RouteLLM blog](https://lmsys.org/blog/2024-07-01-routellm/)
- FrugalGPT [MEASURED in paper; abstract numbers]: LLM cascade can match best single LLM (e.g. GPT-4) with "up to 98% cost reduction", or improve accuracy by 4% at equal cost; API fees differ by two orders of magnitude. — [arXiv 2305.05176](https://arxiv.org/abs/2305.05176)

### Inferences
- A defensible rule set from the primary docs: Haiku 5.5 for triage/classification/summarization/exploration subagents; Sonnet 5.5 default for implementation; Opus 5.5 (or `opusplan`) for planning/architecture review; Fable only for the hardest root-cause or long-running work (explicit opt-in, 5x Sonnet 5.5 input price [DERIVED from pricing table below]).
- Router papers are evidence that cheap-first cascades work when a quality signal exists; for coding agents the practical analogue is tests/CI as the verifier. No source I fetched measured that on coding agents.
- Because each model has its own cache, mid-session model switches carry a re-read penalty (see caching section); tier per task/subagent, not per turn.

### Gaps
- No independent (non-Anthropic) measured routing results on coding agents (SWE-bench-style) found; RouteLLM/FrugalGPT are 2023-24 and pre-agentic.
- Did not fetch OpenAI/Anthropic "model selection" guides beyond Claude Code docs, Latent Space/Hamel/Eugene Yan posts, or any 2026 routing benchmark. The advisor-strategy numbers are for Claude 4.6-generation models; no published numbers for Opus 5.5/Sonnet 5.5/Haiku 5.5 pairings.

## Token-efficiency levers and measured impact

### Takeaway
The largest documented levers are prompt-cache hits (reads cost 0.05-0.1x base input), deferred tool loading (Anthropic reports ~85% fewer tool-definition tokens), keeping context small via /clear and subagent isolation, and batch (50% off). Claude Code now surfaces per-session cache hit rate. Most Anthropic numbers are vendor-run; independent measurements are scarce.

### Cited Findings
- Cache pricing [DOC]: 5-min write 1.25x base input, 1-hour write 2x, read 0.1x (0.05x on Opus 5.5 and Sonnet 5.5; 0.025x on Fable 5.1/Mythos 5.1). Hits refresh the TTL at no extra cost. Min cacheable prompt: 512 tokens (Fable 5.x, Opus 5/5.5, Sonnet 5.5, Haiku 5.5), 1,024 (Sonnet 5, 4.x), 2,048, 4,096 (Opus 4.5/4.6, Haiku 4.5). Cache multipliers stack with batch, long-context, and data-residency modifiers. Cache reads do not count toward ITPM rate limits on most models. — [Prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching); [Rate limits](https://platform.claude.com/docs/en/api/rate-limits)
- Break-even [DERIVED, the docs page states none]: 5-min cache pays off at 2 requests sharing a prefix; 1-hour cache at 3 (using 0.1x reads; sooner with 0.05x). — computed from [Prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)
- Prefix matching is exact: a change anywhere invalidates everything after it. Layer order in Claude Code: system prompt+tool defs, then CLAUDE.md/memory, then conversation. Cache is per model, per speed (fast mode), and (on most models) per effort level; on Opus 5.5/Sonnet 5.5/Haiku 5.5/Fable 5.1 changing effort keeps the cache. [DOC] — [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching)
- Cache-busting actions [DOC]: model switch (including each `opusplan` plan-mode toggle and model-pinned skills), toggling fast mode, adding/removing MCP tools when tool search is off, denying a whole tool when tool search is off, compaction (conversation layer only), accumulating many images, upgrading Claude Code. Cache-safe: editing repo files, editing CLAUDE.md mid-session (but it also doesn't apply until /clear, /compact, restart), permission-mode change, output-style change, skills/commands, /recap, /rewind, toggling `/advisor`. — [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching)
- TTL defaults in Claude Code [DOC]: main conversation gets 1 hour only on a Claude subscription within plan usage; 5 minutes on API key, usage credits, or cloud providers (set `promptCacheTtl`/`CLAUDE_CODE_PROMPT_CACHE_TTL=1h` to change). Subagents, compaction, and other non-main requests default to 5 minutes (`CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL`). Subagents do not read the parent's cache; a fork does. Cache is effectively scoped to machine+directory. — [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching)
- Compaction cost [DOC]: `/compact` sends a summarization request that reads the whole history; cheap when the cache is warm, full uncached price after an idle gap longer than TTL. `/clear` costs nothing. Anthropic advises `/compact` at natural breaks and `/rewind` instead of compaction to abandon a path. Auto-compaction keeps the summary plus five most recently accessed files. — [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching); [Context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Cost-doc hygiene list [DOC]: /clear between unrelated tasks; custom compaction instructions; keep CLAUDE.md under ~200 lines and move workflow-specific instructions to skills (load on demand); prefer CLI tools (`gh`, `aws`) over MCP; disable unused MCP servers; code-intelligence (LSP) plugins to cut exploratory reads; specific prompts; plan mode before implementing; give verification targets; lower effort for simple work. `/usage` plan breakdown attributes usage to skills/subagents/plugins/MCP servers and recommends fixes (e.g. "Trim CLAUDE.md · 49k tokens per request" is the docs' example row). — [Costs](https://code.claude.com/docs/en/costs)
- Hooks as deterministic preprocessing [DOC]: a PreToolUse hook filtering test output (grep for FAIL/ERROR, head -100) can reduce a 10,000-line log from "tens of thousands of tokens to hundreds" (vendor illustration, not a benchmark). — [Costs](https://code.claude.com/docs/en/costs)
- Tool-definition bloat [VENDOR-CLAIMED, internal evals]: Tool Search Tool cut upfront tool context from ~77K to ~8.7K tokens (85% reduction); a 5-server/58-tool setup consumed ~55K tokens upfront; MCP eval accuracy rose Opus 4 49%->74%, Opus 4.5 79.5%->88.1%. Programmatic tool calling cut average tokens on complex research tasks 43,588->27,297 (-37%). Claude Code defers MCP tool definitions by default; only names/instructions enter context. — [Advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use); [Costs](https://code.claude.com/docs/en/costs)
- Subagent isolation [DOC/VENDOR-CLAIMED]: subagents may use tens of thousands of tokens but return ~1-2K token summaries to the parent; but their requests still count against usage and a tree of subagents can multiply spend (defaults: depth 3, concurrency 20). — [Context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents); [SDK subagents](https://code.claude.com/docs/en/agent-sdk/subagents)
- Batch API [DOC]: 50% off input and output on all listed models (e.g. Sonnet 5.5 $1/$5, Haiku 5.5 $0.05/$0.25 per MTok); most batches finish in under 1 hour; stacks with caching; not available with fast mode; not ZDR-eligible (29-day retention). — [Batch processing](https://platform.claude.com/docs/en/build-with-claude/batch-processing); [Pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- Tokenizer inflation [DOC]: Claude 4.7+ models use a tokenizer producing ~30% more tokens for the same text, so per-MTok price comparisons across generations understate the real cost gap. — [Pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- Fast mode [DOC]: Opus 5.5 fast mode $8 in / $40 out per MTok (2x standard); separate cache; first toggle re-reads context uncached at fast rates. — [Pricing](https://platform.claude.com/docs/en/about-claude/pricing); [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching)
- Hidden/background spend [DOC]: background summarization is "typically under $0.04 per session"; scheduled `/loop` tasks, cross-session messages, and goal check-ins re-send full context while a session is idle (goal check-ins capped at 3 per goal since v2.1.246). — [Costs](https://code.claude.com/docs/en/costs)
- Billing-vs-latency: structured outputs and output-length control: I found no fetched source quantifying savings. Output tokens cost 5x input on all current tiers [DERIVED from pricing table], so capping output/effort is the cheapest per-token lever.

### Inferences
- Cache hit rate is the number to watch: with reads at 0.05-0.1x, a 90%-cached session pays roughly 15-20% of uncached input cost [DERIVED: 0.9*0.1+0.1*1.25 = 0.215x on 5m-write/0.1x-read models]. Actual rate is session-specific.
- Practical rules that follow from the docs: pick model+effort at session start; do not toggle MCP/plugins mid-task unless tool search is on; compact at task boundaries, not after idle gaps; run subagents on Haiku; use API-key users' `promptCacheTtl=1h` only if gaps >5 min are common (1h write costs 2x vs 1.25x).
- Deterministic scripts/hooks replacing LLM reads is endorsed by docs but the only quantification is an illustration.

### Gaps
- No independent measurement of CLAUDE.md size vs. cost, compaction vs. handoff-doc workflows, or structured-output savings found.
- Did not read Anthropic's "Prompt caching is everything" post (redirect to claude.dev not followed), so no hit-rate claim from it.
- OpenAI/Gemini caching docs not fetched (OpenAI cached-input prices are in the competitor table below).

## Measurement and attribution: tools, subscription dynamics, per-PR/feature cost

### Takeaway
Claude Code gives `/usage` (list-price estimate + cache stats + plan attribution), status-line fields, an Agent SDK `total_cost_usd`/`modelUsage`, and OpenTelemetry metrics with session/model/subagent/skill/MCP attributes and custom resource attributes; ccusage reads local logs; LiteLLM/Helicone/Langfuse are gateway/observability options. All Claude Code cost figures are client-side estimates, not billing.

### Cited Findings
- `/usage` Session block computes dollars locally from token counts at list price (or a managed `modelPricing` table); "an estimate"; authoritative billing is the Console Usage page. Subscribers' session cost "isn't relevant for billing". Adds `Prompt cache (main)` line (hit share, misses, expected rebuilds, warm/cold; v2.1.251+, likely-cause v2.1.260+), main conversation only (not subagents). — [Costs](https://code.claude.com/docs/en/costs)
- Plan usage breakdown (Pro/Max/Team/Enterprise): attribution to skills, subagents, plugins, MCP servers as % of usage; recommendations for behaviors >=10% of usage; "Loops" rows for scheduled tasks; computed from local history so other devices and claude.ai are excluded. `/insights` analyzes up to 200 sessions into an HTML report. — [Costs](https://code.claude.com/docs/en/costs)
- Typical spend [VENDOR-CLAIMED, enterprise average]: ~$13 per developer per active day, $150-250 per developer per month, <$30/active day for 90% of users. — [Costs](https://code.claude.com/docs/en/costs)
- Agent SDK [DOC]: `total_cost_usd`/`costUSD` are client-side estimates that can drift (pricing changes, unknown model, billing rules) and "do not bill end users or trigger financial decisions from these fields". `modelUsage` gives per-model cost and includes subagents; `usage` excludes subagents; per-step `output_tokens` is a placeholder (read the result message); dedupe parallel tool-call messages by ID. `maxBudgetUsd`/`max_budget_usd` ends the query with `error_max_budget_usd`, counts subagents, refuses new subagents; `maxTurns` per subagent. — [SDK cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking); [SDK subagents](https://code.claude.com/docs/en/agent-sdk/subagents)
- OpenTelemetry [DOC]: metrics `claude_code.cost.usage` (USD) and `claude_code.token.usage` (type: input/output/cacheRead/cacheCreation). Attributes: session.id, user.id/email, organization.id, model, query_source (main/subagent/auxiliary), effort, speed, agent.name, skill.name, plugin.name, mcp_server.name (custom names redacted unless `OTEL_LOG_TOOL_DETAILS=1`), optional `vcs.*` repository attributes (`OTEL_METRICS_INCLUDE_REPOSITORY=true`, v2.1.269+). `OTEL_RESOURCE_ATTRIBUTES` adds department/team/cost_center to every datapoint. Enable with `CLAUDE_CODE_ENABLE_TELEMETRY=1`. — [Monitoring usage](https://code.claude.com/docs/en/monitoring-usage)
- ccusage [DOC, README]: `npx ccusage`; reads local session data of Claude Code, Codex, Gemini CLI, Amp, OpenCode, Copilot CLI etc.; pricing from LiteLLM's price data; reports daily/weekly/monthly/session/blocks (Claude's 5-hour windows)/statusline (beta); table or JSON. README does not state how closely its figures match billing. — [ccusage](https://github.com/ryoppippi/ccusage)
- LiteLLM proxy [DOC]: budgets per virtual key, per user, per team and team member (`max_budget`, `budget_duration`); exceeding returns `budget_exceeded` before the request reaches the provider; budget reservation estimates cost up front to avoid concurrent overrun; per-model budgets are Enterprise; budgets need a database or they are silently unenforced (startup warning only). Anthropic notes several large enterprises use LiteLLM (unaudited, unaffiliated). — [LiteLLM budgets](https://docs.litellm.ai/docs/proxy/users); [Costs](https://code.claude.com/docs/en/costs)
- Helicone [DOC]: `Helicone-Property-[Name]` headers and `Helicone-User-Id`/`Helicone-Session-Id` allow cost grouped "per user, conversation, or feature"; properties can be added after the fact via REST. Page does not document spend caps. — [Helicone custom properties](https://docs.helicone.ai/features/advanced-usage/custom-properties)
- Langfuse [DOC]: records usage and cost per generation; ingested cost takes priority over inferred (model-definition price x usage); dashboards/Metrics API by model, tags, users; threshold alerts. — [Langfuse cost tracking](https://langfuse.com/docs/observability/features/token-and-cost-tracking)
- Console/org controls [DOC]: Console workspace spend limits; auto-created "Claude Code" workspace; Claude Code Analytics API (per-user daily metrics, Admin key); Teams/Enterprise spend report CSV (usage-credit spend only; seat-allowance usage "isn't metered in dollars"). Bedrock/Vertex/Foundry users must use OTel or a gateway for per-user numbers. — [Costs](https://code.claude.com/docs/en/costs)
- Subscription dynamics [DOC]: paid plans have a session limit resetting every five hours plus weekly limits; claude.ai, Claude Code, and Desktop share the pool; usage depends on conversation length, features, model, and effort; usage credits (extra usage) bill beyond the limit, with optional monthly spend limit. Hitting a session/weekly limit cannot be fixed by switching models, but a model-specific (Opus/Sonnet) limit can. The support page gives no Max 5x/20x allowances. Teams/Enterprise seats draw on a per-seat allowance on a rolling 5-hour + weekly window. Fable can bill to usage credits instead of included limits; in `-p` mode it bills without asking. — [Usage limits](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work); [Costs](https://code.claude.com/docs/en/costs); [Model config](https://code.claude.com/docs/en/model-config)
- Attribution to features/PRs: no vendor doc describes a per-PR method directly. The building blocks are `vcs.*` repository attributes and custom `OTEL_RESOURCE_ATTRIBUTES` (OTel), Helicone properties / Langfuse tags (gateway), and Agent SDK per-`query()` `total_cost_usd` (accumulate per run; resumed sessions already include earlier spend, so read the last result, do not sum). — sources as above.

### Inferences
- A simple per-PR approach: run each agent task as its own SDK/`-p` invocation, record `total_cost_usd` and `modelUsage` with the issue/PR id, reconcile weekly against the Console Usage page. Treat as estimates (+/- drift).
- For subscription users, dollar cost is not metered, so the useful KPIs are cache hit rate, `/usage` attribution %, and share of 5-hour/weekly limit consumed per task. API-equivalent cost from ccusage is a proxy only.

### Gaps
- No published method of PR-level cost attribution from a practitioner found; no ccusage-vs-invoice accuracy study found.
- Exact Pro/Max allowance sizes and Max 5x/20x multipliers not verified (support article did not state them).
- Helicone/Langfuse/LiteLLM claims are from docs only; no independent comparison reviewed.

## Budgets, caps, kill switches, and runaway-spend stories

### Takeaway
Hard caps exist at four layers: Console org/workspace spend limits, Agent SDK `maxBudgetUsd`/`maxTurns`/subagent limits, LiteLLM per-key budgets, and subscription spend limits on usage credits. Published horror-story evidence is thin in what I could fetch: one HN title about a $38k Bedrock bill from a caching miss.

### Cited Findings
- API org caps [DOC]: tier spend caps Start $500/mo, Build $1,000/mo, Scale $200,000/mo; Custom has none. You can set your own lower limit on the Billing page. At the tier cap, requests return HTTP 429 `enforced_spend_limit_reached` with no retry-after (SDK retries will keep failing until 00:00 UTC on the 1st); at your own limit, HTTP 400 `invalid_request_error`. Workspace spend/rate limits can be set (not on the default workspace). — [Rate limits](https://platform.claude.com/docs/en/api/rate-limits)
- Rate limits are not spend caps: they are RPM/ITPM/OTPM; docs describe them as intended "to reduce unintentional overspend". Recommended Claude Code per-user TPM falls from 200-300k (1-5 users) to 10-15k (500+ users). — [Rate limits](https://platform.claude.com/docs/en/api/rate-limits); [Costs](https://code.claude.com/docs/en/costs)
- Agent-level controls [DOC]: `max_budget_usd` (counts own spend including subagents; a `/clear` restarts the budget; resumed-session spend does not count), `maxTurns` per subagent (output marked partial), `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` (default 3), `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (default 20), `--max-budget-usd` CLI flag counts data-residency 1.1x. Opus 5 "delegates to subagents more readily than earlier models", so limits matter most there. Idle spend sources: `/loop`, cross-session messages (`crossSessionInbound: hold`), goal check-ins (`CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0`). — [SDK subagents](https://code.claude.com/docs/en/agent-sdk/subagents); [Costs](https://code.claude.com/docs/en/costs)
- Cost-doc diagnosis of "unexpectedly high spend on API/cloud": "usually traces back to long sessions that were never cleared or to Opus left as the default model." [VENDOR-CLAIMED, qualitative] — [Costs](https://code.claude.com/docs/en/costs)
- Subscription caps: Pro/Max usage credits can have a monthly spend limit; with none set the `/usage` row shows "Unlimited". Team/Enterprise: limits at org, group, member level. — [Costs](https://code.claude.com/docs/en/costs)
- Horror story [ANECDOTAL, title only, thread not read]: HN "$38k AWS Bedrock bill caused by a simple prompt caching miss" (8 points, 2026-04-28). — [HN item 47933355](https://news.ycombinator.com/item?id=47933355)
- LiteLLM gotcha [DOC]: without a database, budgets are not enforced. — [LiteLLM](https://docs.litellm.ai/docs/proxy/users)

### Inferences
- Layered defense for a solo founder: (1) Console monthly limit set well below the tier cap, (2) separate workspace/key per agent or repo, (3) `max_budget_usd` + `maxTurns` on every unattended run, (4) explicit subagent depth/concurrency caps, (5) disable idle loops/check-ins in unattended sessions, (6) daily OTel or ccusage read. Items 1-4 are from docs; 5-6 are my synthesis.
- The HN title suggests cache misses (e.g. a gateway stripping `cache_control`, which Claude Code docs warn about) are a realistic runaway-cost class; unverified beyond the title.

### Gaps
- Only one horror-story lead and I did not read its content or fixes. No Simon Willison/Hamel/Latent Space/Reddit budgeting posts retrieved; no data on what typical solo founders cap (numbers) beyond vendor defaults.
- Spend-alert (email threshold) features of the Console were not verified.
